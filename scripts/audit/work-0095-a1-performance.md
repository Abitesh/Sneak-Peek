## Retained changes

- `PromptAssembler.ts`, `ResponsePlanner.ts`, `promptSystemV2.ts`, `SessionPreferences.ts`, `SessionControlsPage.tsx` remove redundant legacy silence, voice and layout instructions for eligible local text turns. Preserve mode contract, authorization, requested subparts/duration/language and the full coding path. Replace contradictory wall-clock wording with length guidance. Definition and capability questions about system design no longer request a design-task reasoning budget. Output guidance does not impose a new token cutoff.
- `LLMHelper.ts` aligns existing empty, opted-in local preload with the shared minimum context allocation. Long contexts still request the larger allocation required to fit the full prompt. No new warm generation or app-owned evidence/KV cache. Ollama uses its own prefix reuse under the same selected model and runner.
- `ContextPlanner.ts`, `ContextTypes.ts`, `ProjectFileScope.ts`, `PromptAssembler.ts` omit mixed snapshots from standalone manual definitions. Keep WORK-0094 follow-ups and confirmed active-résumé project identities. An explicitly missing project excludes unrelated private sources and prompts for the actual gap. Existing project authorization and missing-source policy still govern retrieval. Put the evidence-specific choice policy after the evidence, where the model sees it immediately before generation. This reduced the strength of the false assertion in the measured output but did not make it acceptable.
- `SneakPeekIntelligenceEngine.ts`, `types.ts`, `ipcHandlers.ts`, `scripts/audit/real-world-v205.cjs` add content-free internal stage timings and extend the existing opt-in loopback benchmark to collect native provider timing, IPC observations and substantive frame snapshots. No new provider/API or renderer streaming architecture.
